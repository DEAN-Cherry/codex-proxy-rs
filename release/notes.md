# v3.13.1

## State 配置与展示

- 账号支持多个允许的 State 长度，例如配置 `292,312` 后只接受 292 或 312 字节，不再需要在两个单值之间切换
- 编辑账号时可用逗号输入多个长度、回车添加标签或直接保存，支持逐个删除和自动去重；每个值为 100～2000 的整数，最多 32 个，全部清空后恢复 200～600 字节范围
- 账号列表新增「State」列，按模型显示当前有效票据的实际字节长度；编辑弹窗同步显示长度参考，不返回 State 原文，没有有效票据时显示「未获取」
- 手动刷新 State 完成后自动回读账号列表，更新外部长度展示

## 同步上游更新

- 管理端用量列表与 Dashboard 最近请求在账号邮箱下显示当前备注，按内部账号 ID 关联，已删除账号的历史记录不误关联备注
- 修复第三方客户端及跨客户端续写时的 OpenAI OAuth reasoning 历史兼容问题，HTTP 与 WebSocket 共用规则，API Key 上游保持原有协议
- CCSwitch 导入同时配置当前客户端密钥的日／周额度查询，默认每 30 分钟刷新；新增只读 `GET /v1/usage` 接口，查询不调用上游、不消耗推理并发、不产生用量记录

## 升级说明

- 从本 fork 的 v3.13.0 升级会自动执行 `0020_session_keepalive_expected_lengths.sql`，已有单值长度转换为单元素列表，留空配置继续使用 200～600 字节范围，已发布的 `0001`～`0019` 迁移保持不变
- 管理 API 使用 `sessionKeepaliveExpectedLengths` 数组配置允许长度，显式 `null` 清空，省略保留；旧单值更新字段 `sessionKeepaliveExpectedLength` 仍可提交，账号响应改为数组字段
- 在「账号管理 → 编辑账号 → State 重写」的长度输入框填写 `292,312` 并保存，即可仅接受这两种长度
- 若未显示账号列表的「State」列，可在「显示列」中启用；展示的是查询时符合当前规则的有效缓存票据，不是历史探测日志
- 本版本继续使用 `ghcr.io/dean-cherry/codex-proxy-rs` 镜像与 `DEAN-Cherry/codex-proxy-rs` 更新源，升级前请备份数据库
