# v3.13.3

## State 业务观测

- 修复关闭 State 重写时看不到正常业务响应 State 的问题：无需开启全局或账号重写，正常 Responses 请求收到的 State 也会按账号、实际发送的模型记录并展示
- 覆盖 HTTP 响应头、HTTP SSE 和 WebSocket metadata，以及可取得 State 的上游 HTTP 错误响应头；展示长度、时间与来源，不为观测额外发起探针
- 账号列表与编辑弹窗区分「业务响应」和「刷新结果」，业务观测不受重写模型列表或长度准入规则限制，重写关闭时编辑弹窗仍可查看
- 业务与刷新观测独立记录，按模型展示最近结果；业务来源每账号最多保留最近 64 个模型，账号失效后旧在途请求不能恢复过时观测

## State 长度规则

- 期望 State 长度留空改为不限长度，取消原先默认的 200～600 字节范围；清空所有规则后即可接受任意长度，刷新仍执行原有 HTTP 和格式校验
- 支持单值、闭区间及混合输入，例如 `200,300,400-500` 接受 200、300 和 400～500（含端点）字节
- 支持直接保存、回车添加、去重、排序与逐项删除，拒绝反向区间、小数、负数和溢出值；最多配置 32 个规则，端点为 1～4294967295 的整数
- 区间以紧凑规则保存，不按跨度展开为逐个整数，已有数字列表保持原有匹配含义

## 升级说明

- 从本 Fork 的 v3.13.2 升级会自动执行 `0022_session_state_length_ranges.sql`，将长度规则列由整数数组转换为 JSONB，保留已有数字列表与空配置，已发布的 `0001`～`0021` 迁移保持不变
- 原来留空的长度规则升级后不再限制长度；已显式配置的 `292,312` 等规则继续按配置匹配
- 升级前请备份数据库；迁移后回退到 v3.13.2 或更早版本需要恢复迁移前备份，不能只替换旧二进制或镜像
- 管理 API 的 `sessionKeepaliveExpectedLengths` 现在支持数字与 `{ "min": 400, "max": 500 }` 对象混合，显式 `null` 清空限制，省略保留，旧数字数组和单值更新字段仍兼容；读取端需处理区间对象
- State 观测新增 `source`（`business` / `refresh`），业务来源的 `validation` 为 `observed`；逐帧 metadata 没有独立 HTTP 状态时，`httpStatus` 为 `null`
- 观测仅保留在当前进程，升级或重启后从新的业务响应重新积累，不回填旧版本未记录的历史 State，也不返回 State 原文
