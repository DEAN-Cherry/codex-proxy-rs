# v3.13.2

## State 观测展示

- 账号列表和编辑弹窗按账号、模型展示最近一次刷新响应的 State 字节数、观测时间和校验结果，包括长度不符、格式不符、未返回 State 和上游响应异常
- 最近响应与可用缓存分别展示，例如最近收到 780 字节但校验未通过时，仍可看到之前有效的 292 字节缓存，避免将观测结果误认为缓存已更新
- 手动刷新过程中实时显示响应摘要，停止刷新或关闭弹窗后也会回读列表，保留已经收到的观测
- 观测只包含长度、时间、HTTP 状态和校验结果，不返回 State 原文；每个账号、模型保留最近一项，服务重启后重新采集

## 模型计费

- 补齐 `gpt-6-sol` 和 `gpt-6-luna` 的内置价格，覆盖输入、输出、缓存读取与写入、Flex、Fast 和长上下文档位
- 按官方模型页核对标准价格：Sol 输入 $2、缓存输入 $0.2、输出 $10 / 百万 tokens；Luna 输入 $0.1、缓存输入 $0.01、输出 $0.5 / 百万 tokens
- 两个新模型的搜索工具费用按推理模型规则处理，费用继续按实际发送的模型估算，响应模型字段保留为独立观测

## 同步上游 v3.13.1

- 修复 OpenAI OAuth 请求中下游安装 ID 与账号安装身份混用的问题，HTTP、WebSocket、正文和 turn metadata 保持账号身份一致
- 保留 API Key 上游完整 Codex 模型目录中的推理档位、能力、提示词与未知字段，并按客户端版本请求和缓存目录
- 修复并发额度更新造成的账号快照冲突，在占用并发名额和请求间隔前有限重读并重新校验选号资格
- 默认账号并发上限支持设置为 `0`（不限制），账号独立正数上限继续优先生效，保留在途统计与请求间隔约束
- 修复系统时钟回拨时请求终态保存失败及账号更新时间倒退的问题
- 额度重置确认成功后立即关闭弹窗，后台回读对应账号，保留分页、选择与展开状态；回读失败时明确提示重置已成功
- 连接测试的事件轨迹和原始诊断完整展开，统一使用弹窗外层滚动，并同步上游依赖更新

## 升级说明

- 从本 Fork 的 v3.13.1 升级会自动执行 `0021_unlimited_default_account_concurrency.sql`，仅放宽默认账号并发约束；已发布的 `0001`～`0020` 迁移字节保持不变，原有并发与 State 配置保留
- 对接 Dashboard 或分组管理 API 的客户端需处理 `totalSlots: null`（无限容量）；Dashboard 的 `availableSlots` 在无限容量时也为 `null`，`usedSlots` 继续表示实际在途数
- 账号视图新增 `sessionKeepaliveObservations`，手动刷新结果及 SSE 逐模型事件新增 `observation`；仅携带观测的中间事件不代表刷新完成，现有 `sessionKeepaliveStateLengths` 仍表示当前有效缓存长度
- State 校验通过仅表示响应头满足本地准入规则，不代表完整推理成功或目标模型能力恢复；本版本未改变 State 允许长度规则，也未增加自动模型级降权
- 本版本继续使用 `ghcr.io/dean-cherry/codex-proxy-rs` 镜像与 `DEAN-Cherry/codex-proxy-rs` 更新源，升级前请备份数据库
