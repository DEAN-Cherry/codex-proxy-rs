# v3.13.0

## 新增功能

- 新增可选的 OpenAI OAuth 账号 State 重写能力：通过独立动态代理为选定模型获取 `x-codex-turn-state`，业务请求继续使用原账号出口，功能默认关闭
- 支持按账号配置期望 State 字节长度，填写 100～2000 的整数时精确匹配，留空接受 200～600 字节，保存后可再次清空恢复默认范围
- State 按账号与模型独立缓存到 Redis，缓存期限为 60 分钟，重启后可恢复未过期票据；后台在剩余不足 10 分钟时刷新，缺少有效票据时暂停对应账号／模型的业务请求
- 支持配置探测并发数与重试间隔，连续失败 100 轮后暂停该模型的探测；手动「强制刷新」重置计数和已有探测冷却并重新获取 State，新收到的 429 仍按上游冷却等待
- 账号页面实时展示逐模型刷新结果，支持取消未完成的刷新，已成功写入的票据保留

## 问题修复与体验优化

- 恢复已停用账号时只启用调度，保留已观测额度、凭据错误与冷却状态
- 账号额度预测按当前额度周期计算，减少跨周期数据对剩余额度估算的影响
- OpenAI 容量冷却仅匹配明确的过载信号，避免把其他错误误判为容量不足
- 在线更新在后台执行并保留发布说明，密钥使用页新增版本信息入口，长上下文计费以黄色提示图标标识
- State 探测使用 TLS 证书校验，诊断日志对路由票据、账号令牌及代理认证脱敏

## 使用与升级说明

- 从 v3.12.1 升级会自动执行新增的 `0017`～`0019` 数据库迁移，原有 `0001`～`0016` 迁移保持不变，升级前请备份数据库
- 使用 State 重写前，在「代理管理」保存一个动态代理并测试通过，再到「系统设置 → 上游配置」开启全局功能，最后为账号开启重写并选择实际的上游模型 ID
- 探测会产生模型调用消耗，State 长度与套餐、模型质量之间没有官方保证；该功能跨轮次复用 State，属于可选实验性行为，不保证改善所有账号或出口的表现
- 实验分支与当前版本的迁移编号不同，不支持直接复用实验分支数据库的迁移历史
- 本版本由 `DEAN-Cherry/codex-proxy-rs` 的 GitHub Actions 构建，Docker 镜像为 `ghcr.io/dean-cherry/codex-proxy-rs:3.13.0`，随包 Compose 使用此仓库的镜像和更新源
- 已有部署需将 `CPR_IMAGE` 和 `CPR_UPDATE_REPOSITORY` 改为本仓库对应值；原生归档部署如需从本仓库检查更新，设置 `CPR_UPDATE_REPOSITORY=DEAN-Cherry/codex-proxy-rs`
